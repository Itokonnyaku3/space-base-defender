## 0. このゲームの「核」の言語化

現仕様（超低速・慣性移動・5秒チャージの予測射撃・タレット配置・通信と選択・僚機指示）を貫く一本の柱はこれだと考える:

> **「反射神経の代わりに、情報と事前の決断が勝敗を決めるゲーム」**

- 弾が遅い → **未来位置を読む**ことが攻撃
- 船のような操舵 → **数秒先の自分**を操作する
- Fog of War とレーダー → **情報そのものが資源**
- タレット・中継器・僚機指示 → **戦闘前の準備と配置**が戦力

以降の提案はすべてこの柱を太くする方向で選んでいる。「速くする」「物量を増やす」系のアイデアは意図的に外した（参考作のソビエトストライク/サドンストライクも「考えて配置する重さ」が魅力の作品）。

## 1. ゲームループの強化（リプレイ性）

### 1-A. 戦果評価とメダル（実装コスト: 小 / 効果: 大）★最優先候補

Wave クリア時に「無傷の砦（基地被弾0）」「完全護衛（輸送船HP90%以上）」「電撃戦（N秒以内）」などの**勲章**をリザルト表示する。

- **なぜ効くか**: 低速ゲーは1プレイが長い。「クリアしたか」だけでなく「どう上手くクリアしたか」の軸を足すと、同じ Wave を別解で遊び直す動機になる。
- **実装の足場**: `ScenarioManager` の `clearConditions` 判定と同じ構造で `medalConditions` を `WaveConfig` に追加するだけ。進捗カウンタ（`waveProgress`）は既にある。リザルト画面は ARCHITECTURE_REVIEW Phase 3 の `GameOverScene` と同時に `WaveResultScene` として作ると一石二鳥。
- **データ駆動**: メダル定義はシナリオ JSON に置けるので、シナリオエディタで編集可能になる。

### 1-B. 選択肢に「毎回トレードオフ」を持たせる（実装コスト: 小〜中）

Yes/No 通信分岐は実装済み（`stateFlags.allyRescued`）だが、現状フラグが1個固定。これを**汎用フラグ辞書**に拡張し、すべての選択を「何かを得て何かを失う」設計にする。

例:
- 「救難信号に応じる」→ 僚機+1、ただし応援に行った隙に基地へ強襲イベント
- 「本国へ増援要請」→ 次 Wave で僚機+2、ただし敵も増える（要請通信を傍受される）
- 「中継器の予備部品を輸送船から降ろす」→ 中継器コスト半減、ただし輸送船の速度低下

- **なぜ効くか**: 「正解の選択肢」があると2周目以降は作業になる。トレードオフなら**周回ごとに違うビルドが生まれる**。
- **実装の足場**: `ScenarioManager.stateFlags` を `Record<string, boolean>` に一般化し、シナリオ JSON の `flagCondition` を任意キー対応に（現在 `allyRescued` 固定 — ScenarioManager.ts:406 の as キャストを外すだけに近い）。アクションに `set_flag` タイプを追加。

### 1-C. ランダム小事件（スパイス）（実装コスト: 中）

Wave 中に低確率で発生する短いイベントをプールから抽選:

- **漂流コンテナ**: 回収（接触して3秒静止）でポイント or 一時バフ。低速機動だから「取りに行くか守りに残るか」が判断になる
- **ソーラーフレア**: 30秒間レーダー無効（事前に通信で予告 → タレット配置で備える時間を与える）
- **敵の補給ミス**: 1分間だけ敵前哨基地の生産停止 →「今が攻め時」の号令

- **実装の足場**: `dynamicEvents` の仕組み（条件付きセリフ選択 + アクション）がほぼそのまま使える。`triggerDynamicEvent` を時間抽選で呼ぶ `RandomEventSystem` を足すだけ。
- **注意**: ランダムは「有利にも不利にもなる」中立イベント中心に。理不尽な不利だけだとリプレイ意欲を削ぐ。

### 1-D. シナリオエディタを「コンテンツ量産装置」へ昇格（実装コスト: 中〜大 / 長期）

1816行のエディタは既に大きな資産。`schemaVersion` + zod 検証（ARCHITECTURE_REVIEW Phase 5）を入れた上で、**シナリオの書き出し/読み込みを共有可能なファイル形式**として確立すれば:

- 自作シナリオの差し替えプレイ（実質ステージエディタ）
- 「公式シナリオ＋お題シナリオ（タレット禁止縛り等）」の配布

ルール（`WaveConfig.rules`）が実装に接続されれば（同 Phase 4）、エディタが**ゲームモード生成器**になる。

## 2. 手触り・演出（ジューシーさ）

> 低速ゲーの手触りは「キビキビ」ではなく「**重さと確かな手応え**」で作る。
> 以下はすべて既存の `Graphics` / `triggerExplosion` / `SoundEffects` の延長で安価に足せるものから並べている。

### 2-A. 着弾予測線（リード照準ゴースト）★コア体験の直結強化

長距離弾は「初速25→2秒かけて350に加速」という独特の弾道（MainScene.ts:914-924）。これは面白い仕様なのに、**プレイヤーが学習する手段が画面にない**。

- 機首方向に薄い点線で「t秒後の弾の位置」を3点ほどゴースト表示（チャージ完了時のみ）
- 慣れたプレイヤーは消せるオプションに

**実装**: 弾道は等加速度なので `位置 = v0*t + 0.5*a*t²` の純関数。`cooldownGraphics` と同じ Graphics 1枚に毎フレーム描くだけ。**この計算関数はそのまま単体テストの題材になる**（Phase 5 と相性◎）。

### 2-B. 速度ベクトルの可視化（操舵感の強化）

慣性ドリフト中、自機から「現在の速度ベクトル矢印」と「3秒後の到達予測点」を薄く表示。

- **なぜ効くか**: 「船を操っている」感覚は、**自分の慣性が見える**ことで初めて気持ちよさに変わる。見えないと単に「言うことを聞かない機体」と感じられてしまう。
- **実装**: `body.velocity` を矢印描画するだけ（10行程度）。

### 2-C. 画面シェイク＋ヒットストップ微量（1行級の効果大ネタ）

- 撃破時: `this.cameras.main.shake(60, 0.002)`
- 前哨基地・母船撃破時: シェイク強め + `this.time.timeScale = 0.3` を200msだけ（スローモーション）→ 多段爆発
- 被弾時: 一瞬だけ画面端を赤くフラッシュ（Graphics 1枚）

**注意**: 低速ゲーなので「常時ガタガタ」は禁物。**大物撃破の瞬間だけ**に絞ることで、静→動のコントラストが効く。

### 2-D. 撃破確認の無線ログ演出

`debug-log-add` で既に全イベントが流れている。これを世界観に取り込み、**デバッグモードでなくても画面隅に小さく「戦術無線」風の3行ログ**を流す（「敵編隊シルバー、沈黙を確認」「中継器03、応答なし！」）。

- **なぜ効くか**: ソビエトストライク的な「管制と繋がっている」臨場感が、既存資産（ログ＋通信UI）の流用だけで出る。
- **実装**: DebugLogUI の簡易版コンポーネント。メッセージの言い換えテーブルを configs に。

### 2-E. エンジン音・チャージ音の連続フィードバック

`SoundEffects` は単発音のみ。足すべき連続音は2つだけ:

1. **推進音**: ブースト中はピッチ上昇（ノイズ＋ローパス、`AudioContext` で20行程度）
2. **長距離弾のチャージ完了音**: 5秒CTの「残り0.5秒でチャイム→完了でカチッ」。**画面を見ずに**次弾タイミングが分かるようになり、視線をレーダーや敵に使える＝「考えるリソース」が増える

### 2-F. タレット設置のプレビューゴースト

現在 SPACE 一発で即設置。設置前に**射程円とゴーストを表示 → もう一度押して確定**にすると、「配置を考える」気持ちよさが出る（タワーディフェンスの定石）。射程は `TURRET_CONFIGS.standard.range` を参照（Phase 4 の config 一元化が前提）。

## 3. このシステムだからこそ映える拡張ギミック

### 3-A. 通信傍受システム ★本作の核と最も相性が良い提案

**敵のスポーンを「傍受した敵信号」として事前予告する**。

- 中継レーダー網のカバー範囲が広いほど、予告の精度と猶予が上がる
  - 圏外: 予告なし（突然来る）
  - 1段階: 「北東方面に通信増大」（方角のみ、30秒前）
  - 2段階: 「編隊3機、前哨基地βより発進」（種類と発進元、60秒前）
- 予告を受けて**タレットを置く/僚機を回す/自分が迎撃に出る**の決断がゲームの中心になる

**なぜこれか**: 低速ゲーは「来てから反応」では間に合わないのが本質。**事前情報→配置→結果**のループは Fog of War・中継器・通信UIという既存の3資産を1つの意味に束ねる。「中継器を守る理由」も劇的に強くなる（現在は視界だけ）。

**実装の足場**: スポーンは `EnemySpawnManager` に集約済みなので、スポーン予定をキューに変えて「予告イベント発火 → N秒後に実スポーン」にするだけ。予告文は `dynamicEvents` の仕組みで世界観に乗せられる。中継器カバー判定は `sendRadarData` の `visionCircles` 計算を流用。

### 3-B. 僚機への戦術指示ホイール（サドンストライク要素の深化）

Q キー指示（座標移動のみ）を、押している間だけ出る**4方向ホイール**に拡張:

| 指示 | 挙動 | 実装メモ |
|---|---|---|
| 護衛 | 自機/輸送船に追従（現在のデフォルト） | 実装済みロジック流用 |
| 強襲 | 指定地点の敵・建造物を攻撃 | `allyTargetPos` 流用 |
| 修理 | 最寄りの損傷タレット/中継器へ | タレット修理は実装済み(MainScene.ts:1595)。対象を中継器にも拡張 |
| 哨戒 | 指定点を周回し発見時に無線報告 | 3-A の傍受と連動すると強い |

**前提**: ARCHITECTURE_REVIEW Phase 3 で `AllySystem` を分離してから着手（現在の updateAllies は分岐が深く、ここに足すとデグレ必至）。

### 3-C. 補給線（電力ライン）システム

タレット・中継器は「基地または中継器から一定距離内」にある時だけフル性能。圏外だと連射速度半減＋レーダー寄与なし。

- 中継器が**視界＋兵站の二役**になり、「基地から外へ伸びるネットワークを設計する」ストラテジー性が生まれる
- 敵 AI には既に中継器を狙う挙動があるため、「補給線の節を切られる」緊張感が自然に発生する
- 画面上は基地→中継器→タレットを淡い線で結ぶだけで「自分の勢力圏」が可視化され、見た目にも気持ちいい

**実装の足場**: `visionCircles` と同じ「円の連結判定」。Union-Find か単純な BFS で 30 行程度の純関数 → テスト可能。

### 3-D. 司令官モード（時間圧縮）

敵影がない時に**2倍速**（敵接近 or 通信受信で自動解除）。

- 低速ゲー最大の弱点「待ち時間」への正攻法の解。プレイヤーに「今は安全」というメタ情報を与える効果もある
- **実装**: `this.time.timeScale` と `this.physics.world.timeScale` の同時変更（Phaser 標準機能）。BGM はそのまま流す（世界だけが早回しになる演出が SF 的に映える）

### 3-E. ボスコニアン式・前哨基地のコア露出

前哨基地（現在は単なる高HP矩形）に構造を持たせる:

- 周囲6方向に砲台パーツ、中央にコア。**コアは砲台を2つ以上壊した「開口部」からしか撃てない**
- 低速・慣性移動だからこそ「どの角度から進入するか」のポジショニング自体が攻略になる（本家ボスコニアンのコア撃ち＝正面突入のリスペクト）

**実装の足場**: 前哨基地を「親 Sprite + 子パーツ群」のコンポジットに。Phase 3 の `HealthSystem`（部位ごとの HP）導入後なら自然に書ける。

### 3-F. 偽の救難信号（情報の真偽を問う）

通信 UI の世界観を逆手に取り、たまに**罠の救難信号**を混ぜる。

- ノイズ混じり・座標が不自然・送信者名が微妙に違う、などの「見抜くヒント」をテキストに仕込む
- 助けに行くと伏兵、無視すると本物だった場合に僚機を失う
- 1-B の汎用フラグと組み合わせ、「疑い深い指揮官」「お人好し」で後の通信内容が変わる

**なぜ効くか**: 「情報が資源」という核を、戦術レイヤー（レーダー）だけでなく**物語レイヤーでも**機能させる。プレイヤーがテキストを真剣に読むようになり、通信 UI への投資（タイピング演出・表情差分）が最大限回収される。
